# Docker 核心概念与常用命令速查表

对于后端开发来说，Docker 是必备的技能。如果你觉得它很难理解，不妨把它想象成**“集装箱与货船”**。

## 0. 到底什么是 Docker？它是怎么工作的？(小白秒懂版)

很多初学者觉得 Docker 抽象，是因为没有搞懂它和“传统虚拟机（VMware/VirtualBox）”的区别。

### 痛点：为什么会有 Docker？
程序员最怕听到的一句话是：“**这段代码在我的电脑上跑得好好的，怎么到你的电脑/服务器上就报错了？**”
这通常是因为操作系统的版本、环境变量、或者依赖库不一致导致的。
Docker 的出现就是为了解决这个问题：**它不仅把你的“代码”打包，还把你代码运行需要的“整个系统环境（除内核外）”一起打包了！**保证了“开发环境”与“生产环境”的绝对一致。

### 核心原理解析：虚拟机 vs Docker 容器

为了方便理解，我们打个比方：**你要在同一块地皮上（宿主机物理硬件）给人提供住宿（运行应用程序）。**

#### 1. 传统虚拟机 (Virtual Machine) = **“盖独栋别墅”**
*   **原理**：使用 VMware/VirtualBox 等软件，先虚拟出全套的硬件（主板、CPU、内存），然后在上面安装一个**完整的、庞大的操作系统（Guest OS）**，最后才安装你的应用。
*   **缺点**：太重了！为了跑一个 10MB 的程序，你得先开机运行一个几 GB 的操作系统。启动慢（分钟级），非常浪费内存和 CPU 资源。

#### 2. Docker 容器 (Container) = **“盖一栋大楼，划分精装公寓”**
*   **原理**：Docker **不需要**虚拟底层硬件，也**不需要**安装完整的客户操作系统。所有的 Docker 容器都**直接共享你当前电脑（或服务器）的操作系统内核**。
*   **隔离魔法 (底层技术)**：Docker 在共享内核的基础上，使用了 Linux 的两项核心技术来实现“隔离”：
    1.  **Namespace (命名空间 - 视觉隔离)**：给每个公寓建了一堵“隔音墙”。每个容器在里面只能看到自己的文件系统、自己的网络 IP、自己的进程，完全不知道外面还有别的租户，以为自己独占了一台电脑。
    2.  **Cgroups (控制组 - 资源限制)**：给每个公寓装了独立的“水电表”。限制这个容器最多只能用 1GB 内存和 1 个 CPU 核心，防止某个“租户”乱挖矿把整栋大楼（整台宿主机）拖垮。
*   **优点**：极度轻量！没有冗余的操作系统，容器的大小通常只有几十兆，启动只需要**毫秒级**。一台普通服务器可以轻松同时跑成百上千个容器。

**总结**：Docker 不是虚拟机，它是一种**更高级的“进程隔离”技术**。它把程序及其依赖装进一个“集装箱”，让程序在隔离的环境中安全、快速地运行。

## 1. 核心概念：镜像、容器与仓库

*   **Image (镜像)**：相当于**“安装光盘”或“蓝图”**。它是只读的，包含了运行程序所需的一切（代码、运行环境、依赖库、系统配置）。比如 `mysql:8.0` 镜像。
*   **Container (容器)**：相当于**“运行起来的程序”**。你用“安装光盘（镜像）”在电脑上装好并启动的那个软件，就是容器。一个镜像可以启动无数个一模一样的容器。
*   **Repository (仓库)**：相当于**“应用商店”**。比如 Docker Hub，里面放着全世界开发者做好的镜像，你可以直接 `pull`（下载）下来用。

## 2. 常用命令速查表

### 2.1 镜像操作 (光盘管理)

| 场景 | 命令 | 说明 / 比喻 |
| :--- | :--- | :--- |
| **下载镜像** | `docker pull <镜像名>:<版本>` | 从应用商店下载光盘。如 `docker pull mysql:8.0`，不加版本默认下载 `latest` 最新版。 |
| **查看本地镜像** | `docker images` | 查看你抽屉里现在有哪些光盘。 |
| **删除镜像** | `docker rmi <镜像名或ID>` | 把抽屉里的某张光盘扔掉。如果这个光盘正在被使用（有运行的容器），会报错。 |
| **打包镜像** | `docker build -t <名字> .` | 根据当前目录的 `Dockerfile`，自己刻录一张新光盘。 |

### 2.2 容器操作 (程序运行管理) —— 最常用！

| 场景 | 命令 | 说明 / 核心参数 |
| :--- | :--- | :--- |
| **启动新容器** | `docker run [参数] <镜像名>` | 用光盘安装并运行程序。这是**最复杂**但也**最常用**的命令，见下文详细拆解。 |
| **查看运行中的** | `docker ps` | 查看当前货船上正在跑的集装箱。加上 `-a` (`docker ps -a`) 可以看所有（包括已停止的）。 |
| **停止容器** | `docker stop <容器名或ID>` | 正常关机（给程序发送退出信号，让它保存好数据再关）。 |
| **强制杀死** | `docker kill <容器名或ID>` | 直接拔电源。 |
| **启动已停止的** | `docker start <容器名或ID>` | 把关机的容器重新开机。 |
| **重启容器** | `docker restart <容器名或ID>` | 重启（常用于修改配置后）。 |
| **删除容器** | `docker rm <容器名或ID>` | 把集装箱扔下海。加上 `-f` 可以强制删除正在运行的容器。 |

### 2.3 进入容器与查看日志 (查Bug神器)

| 场景 | 命令 | 说明 / 比喻 |
| :--- | :--- | :--- |
| **查看日志** | `docker logs -f <容器名>` | 查看程序打印的日志。`-f` 表示像 `tail -f` 一样持续滚动刷新。**排错必用！** |
| **进入容器内部** | `docker exec -it <容器名> bash` | 就像用 SSH 登录到另一台 Linux 电脑上。有些精简镜像没有 bash，可以换成 `sh`。 |

## 3. 核心大招：`docker run` 参数详解

每次我们在本地启动 MySQL 或 Redis 时，都会敲一长串命令。搞懂这些参数，你就彻底掌握了 Docker。

**以启动 MySQL 为例：**
```bash
docker run -d --name my_mysql -p 3307:3306 -e MYSQL_ROOT_PASSWORD=123456 -v mysql_data:/var/lib/mysql mysql:8.0
```

**参数逐一拆解：**
*   **`-d` (Detached 后台运行)**：让容器在后台默默跑，不霸占你的终端窗口界面。
*   **`--name my_mysql` (命名)**：给这个集装箱起个好记的名字，以后 `docker stop my_mysql` 就不用去背那串随机的容器 ID 了。
*   **`-p 3307:3306` (端口映射 Port)**：**极其重要！**
    *   **左边 3307** 是你宿主机（你自己的 Windows/Mac）的端口。
    *   **右边 3306** 是容器内部 MySQL 的默认端口。
    *   **意义**：如果你本地已经装了一个 MySQL 占用了 3306，你可以把左边改成 3307。你的代码里连 `localhost:3307`，Docker 就会自动把流量转发到集装箱里面的 `3306` 端口去。
*   **`-e MYSQL_ROOT_PASSWORD=123456` (环境变量 Environment)**：传给容器内部的环境变量。这里是告诉 MySQL 初始化时把 root 密码设为 123456。
*   **`-v mysql_data:/var/lib/mysql` (数据卷映射 Volume)**：**极其重要！**
    *   **痛点**：如果你不加这个参数，当你在容器里建了表、存了数据，一旦你不小心敲了 `docker rm` 删除了容器，**所有数据瞬间灰飞烟灭**！
    *   **意义**：`-v` 就像是插了一根 U盘。它把你宿主机的某个文件夹（或命名数据卷），和容器内部存储数据的文件夹（`/var/lib/mysql`）**打通**。哪怕容器被删了，数据依然安全地保存在你的宿主机硬盘上。下次启动新容器，只要挂载同一个卷，数据瞬间恢复。
*   **`mysql:8.0`**：最后这个位置，指定你要用哪张“光盘（镜像）”来启动。

## 4. 进阶大招：Docker Compose

当你的项目越来越大，你不仅需要 MySQL，还需要 Redis、RabbitMQ、甚至你自己写的 Go 后端。
如果每次都要手敲 4 遍 `docker run` 并记住那么多参数，简直是折磨。

**Docker Compose 就是来解决这个问题的：**
你可以写一个 `docker-compose.yml` 剧本文件，把所有的服务、端口映射、环境变量都写在里面。
然后只需要在文件所在目录敲一行命令：
```bash
docker-compose up -d
```
Docker 就会自动帮你把所有服务按顺序启动，并把它们放在同一个局域网里（互相可以通过名字如 `mysql` 访问，不需要 IP）。
关闭也很简单：
```bash
docker-compose down
```

## 5. 容器间的互相通信：它们怎么“打电话”？

既然每个容器都是一个互相隔离的“精装公寓”，那如果“Go 后端容器”想要连接“MySQL 容器”去存取数据，它们该怎么互相通信呢？

### ❌ 误区：千万别用内网 IP 直接连！
每个容器启动时，Docker 都会给它分配一个内部 IP（比如 `172.17.0.2`）。但**绝对不要在代码里写死这个 IP**！因为一旦容器重启，这个 IP 可能会变，你的程序就找不到数据库了。

### ✅ 正确姿势：使用 Docker 自定义网络 (内网 DNS)
我们可以给这些容器建一个“内部局域网”。在这个局域网里，容器之间可以直接通过**容器的名字**互相访问，Docker 的内部 DNS 会自动帮你把名字解析成正确的 IP。

#### 方法一：纯手工接线 (docker run 进阶)
1. **新建一个局域网**：`docker network create my_app_net`
2. **把 MySQL 接入这个网**：`docker run -d --name my_mysql --network my_app_net mysql:8.0`
3. **把 Go 后端也接入这个网**：`docker run -d --name my_go_app --network my_app_net my_go_image`

*结果*：在 Go 代码里，连接数据库的地址直接写 `my_mysql:3306` 即可！Docker 会自动找到那个名叫 `my_mysql` 的容器，完全不用关心它的 IP 是什么。

#### 方法二：最优雅的终极方案 (Docker Compose 自动接线)
上面纯手工建网络太麻烦了。在实际开发中，我们几乎 100% 使用 **Docker Compose**。
当你使用 `docker-compose.yml` 启动多个服务时，**Docker Compose 会在后台自动为它们创建一个专属的局域网**，并把所有服务都拉进去。

你只需要在配置文件里定义服务名：
```yaml
services:
  mysql_db:
    image: mysql:8.0
  redis_cache:
    image: redis:7.0
  go_backend:
    image: my_go_app
```
*结果*：在 `go_backend` 的代码里，直接连接 `mysql_db:3306` 和 `redis_cache:6379` 就能完美通信，完全不用操心 IP 和网络配置！这就是为什么我们强烈推荐使用 Docker Compose 编排微服务。
