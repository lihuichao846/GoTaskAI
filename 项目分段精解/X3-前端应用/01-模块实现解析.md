## 0. 一句话总览

**X3 = 一个"零框架依赖"的 Vue3 单页应用：没有路由库、没有 Pinia/Vuex、没有组件库，只用 `ref` + `computed` + 一个 `App.vue` 把「五视图切换、认证、任务列表、SSE 实时更新、对话渲染」全部手写出来。**

```
浏览器 (Vite 构建的 Vue3 SPA, :5173)
   │  ① REST: fetch + Bearer <token>        →  Go API (:8080)   [CORS 反射 Origin]
   │  ② SSE : EventSource /api/tasks/stream?token=<token>
   ▼
localStorage['gotaskai_token']  ← 唯一的"登录态持久化"
```

它刻意**不引入任何状态管理库**：整个应用的可变状态就是 `App.vue` 里约 25 个 `ref`，其中 `tasks` 是全局共享的"任务真相"，其余视图（Agent / 工具 / 知识库）各自持有自己的局部 `ref`。这是"**能跑通的最小形态**"，也是本文档要重点标注的问题来源——很多缺陷正是"手写状态管理 + 手写 SSE 重连"带来的。

## 1. 这个模块解决什么问题

### 1.1 它从哪里来

`web/` 是**从旧的单文件页面迁移出来的第二入口**。证据在代码注释与文案里：

- 登录页文案：`这是从旧版单文件页面迁移出的第一批能力…`（[AuthPanel.vue](file:///d:/Program%20Files/GoTaskAI/web/src/components/AuthPanel.vue#L42-L44)）
- 首屏 hero：`前后端分离后的独立前端工作台`（[App.vue](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L547-L550)）

也就是说：**Go 服务端仍托管着一份旧的 `public/index.html`**（[cmd/api/main.go](file:///d:/Program%20Files/GoTaskAI/cmd/api/main.go#L120) 的 `r.StaticFile("/", ..."public", "index.html")`），而 `web/` 是新版独立工程。两者并存——这一点在第 9 节会变成一个"构建产物没有自动接线"的实际问题。

### 1.2 没有它（或没有独立前端）会怎样

| 缺什么 | 后果 |
|---|---|
| 独立前端工程 | 所有 UI 挤在服务端模板/单文件里，无法用 HMR、无法组件化、无法独立部署 |
| SSE 长连接 | 任务状态只能靠用户手动刷新，异步任务"发出去就没影了" |
| 认证态持久化 | 刷新页面即掉登录态 |
| SSE 消费链路 | 对话/工具调用轨迹无法"边跑边看" |

### 1.3 它覆盖了哪几条端到端能力

```
① 认证        登录 / 注册 / 登出 / localStorage 恢复
② 对话        选 Agent → 发消息 → 建会话 → runAgent → SSE 回填 → 渲染气泡
③ 任务        任务列表（全量）+ 按 ID 查单个任务（任务中心）
④ Agent/工具/知识库  三个管理面板（各自 CRUD + 绑定）
⑤ 实时        SSE 双事件流：task_update（任务）+ tool_call（工具轨迹）
```

## 2. 技术栈与工程形态

### 2.1 依赖清单：只有 Vue 一个

```json
// web/package.json:11-17
"dependencies": { "vue": "^3.5.18" },
"devDependencies": { "@vitejs/plugin-vue": "^5.2.1", "vite": "^5.4.19" }
```

**这是全篇最重要的一个事实**：生产依赖**只有 `vue`**。

| 类别 | 用了什么 | 代码里的证据 |
|---|---|---|
| 框架 | **Vue 3.5**（`<script setup>` 组合式 API） | 全部 `.vue` |
| 构建 | **Vite 5**（`vite` / `vite build` / `vite preview`） | [package.json](file:///d:/Program%20Files/GoTaskAI/web/package.json#L6-L10) |
| 路由 | **没有**（无 `vue-router`） | 见 §3 的"视图切换" |
| 状态管理 | **没有**（无 `pinia` / `vuex`） | 见 §6 |
| UI 组件库 | **没有**（无 Element/Ant） | 所有 DOM 手写 |
| HTTP | **原生 `fetch`**（无 axios） | [client.js](file:///d:/Program%20Files/GoTaskAI/web/src/api/client.js#L20-L33) |
| 实时 | **原生 `EventSource`** | [client.js](file:///d:/Program%20Files/GoTaskAI/web/src/api/client.js#L104-L106) |
| 图标 | **内联 SVG**（无图标库） | [App.vue](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L638-L663) |

**为什么这是个可讲的设计选择**：把依赖压到"只有 Vue"，换来的是**零版本冲突、零供应链风险、极小的构建体积**；代价是**所有基础设施要手写**（路由、状态、请求重试、SSE 重连、401 拦截），而手写的东西天然缺少边界处理——这正是第 12 节缺陷清单的来源。

### 2.2 路由是怎么被"省"掉的：`activeView` 一个字符串

没有路由器，只有一个 `ref`：

```js
// App.vue:47
const activeView = ref('workspace')
```

加上一张"视图 → 标题/描述"的映射表：

```js
// App.vue:49-66
const navItems = [
  { key: 'workspace', label: '工作台' },
  { key: 'agents',    label: 'Agent' },
  { key: 'tools',     label: '工具' },
  { key: 'kb',        label: '知识库' },
  { key: 'tasks',     label: '任务中心' }
]
const viewMeta = computed(() => {
  const meta = { workspace: {...}, agents: {...}, tools: {...}, kb: {...}, tasks: {...} }
  return meta[activeView.value] || meta.workspace
})
```

模板里用 `v-if` 决定渲染哪个面板（[App.vue](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L715-L893)），导航按钮直接 `@click="activeView = item.key"`（[App.vue](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L634)）。

**直接后果（必须知道）**：

1. **没有 URL**：刷新页面永远回到 `workspace`，**无法分享/收藏某个视图的直达链接**，浏览器后退键不改变视图；
2. **视图切换 = 组件卸载重建**：因为用的是 `v-if` 而不是 `v-show`，每次切到"工具"都会重新 `onMounted` 拉一次数据（`ToolList.vue:96` 的 `onMounted(refresh)`），**切换即重新请求**；
3. 好在"重建"也让 `token` prop 天然是新鲜的——见 §4.3 的一个隐患。

### 2.4 与后端如何对接：环境变量基址 + 后端 CORS（**没有用 Vite 代理**）

```js
// web/src/config/env.js:1-2

  import.meta.env.VITE_API_BASE_URL?.trim() || 'http://localhost:8080'
```

```ini

```

所有请求都经过同一个拼接函数：

```js

  return `${apiBaseUrl}${path}`
}
```

**关键点：`vite.config.js` 里没有 `server.proxy`**（整个文件只有 9 行，只配了 `plugins` 与 `server.host/port`）：

```js
// web/vite.config.js:1-9
export default defineConfig({
  plugins: [vue()],
  server: { host: '0.0.0.0', port: 5173 }
})
```

所以开发时前端（:5173）是**真跨域**直连后端（:8080），依赖后端放行 CORS：

```go
// internal/middleware/cors.go:13-20
origin := c.GetHeader("Origin")
if origin != "" {
    c.Header("Access-Control-Allow-Origin", origin)   // ★ 反射任意 Origin
    c.Header("Vary", "Origin")
    c.Header("Access-Control-Allow-Headers", "Authorization, Content-Type, Accept, Origin, Cache-Control")
    c.Header("Access-Control-Allow-Methods", "GET, POST, PUT, PATCH, DELETE, OPTIONS")
    ...
}
```

> ⚠️ `Access-Control-Allow-Origin` 直接**回显请求方 Origin**、没有白名单。因为没有用 Cookie（注释明写"不依赖 Cookie 凭证"，`cors.go:10`），所以不构成典型的 CSRF；但这等于**对全互联网开放 API 读取**（凭据仍需 JWT）。生产建议改成允许列表。**（代码事实）**

**三种运行形态**（都从代码推导，未逐一实测）：

| 形态 | 前端从哪来 | 后端从哪来 | 依据 |
|---|---|---|---|
| 开发 | Vite dev server `:5173` | `go run ./cmd/api` `:8080` | [run_fullstack_dev.bat](file:///d:/Program%20Files/GoTaskAI/run_fullstack_dev.bat#L8-L14) |
| 生产（Nginx） | Nginx 静态目录 `/usr/share/nginx/html`（卷映射自宿主机 `./public`） | 反代到 `host.docker.internal:8080` | [nginx.conf](file:///d:/Program%20Files/GoTaskAI/nginx.conf#L25-L43) + [docker-compose.yml:193](file:///d:/Program%20Files/GoTaskAI/docker-compose.yml#L193) |

**第三种形态值得单独点出**：Go 服务托管的 `<root>/public/index.html` 是**旧的单文件页面**（仓库根有 `public/index.html`），**不是 `web/` 的构建产物**。也就是说 `npm run build` 生成的 `web/dist/` **不会被 Go 服务自动拾取**——详见 §12.11。

## 4. 认证态管理

### 4.1 token 存在哪：两个 localStorage key

```js
// App.vue:22-26
const tokenKey = 'gotaskai_token'
const usernameKey = 'gotaskai_username'

const authToken = ref(localStorage.getItem(tokenKey) || '')
const username  = ref(localStorage.getItem(usernameKey) || '')
```

| 项 | 值 |
|---|---|
| token 存储位置 | `localStorage`，key = **`gotaskai_token`** |
| 用户名存储位置 | `localStorage`，key = **`gotaskai_username`** |
| 登录判据 | `isLoggedIn = computed(() => Boolean(authToken.value))`（[App.vue:68](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L68)） |

**只判断"有没有 token"，不判断"token 是否还有效"**——这一条后面会引出 §12.4 和 §12.6 两个真实问题。

### 4.2 启动恢复：`onMounted` 里有 token 就直接连

```js
// App.vue:527-534
onMounted(() => {
  if (authToken.value) {          // ← 从 localStorage 恢复出来的 token
    initTaskStream()              // ① 立刻建 SSE
    refreshTasks()
    refreshAgents()
    refreshConversations()
  }
})
```

**注意顺序**：**先建 SSE，再拉 REST**。这样做能减少"任务在 REST 返回前就更新了"的窗口，但仍存在竞态：如果一条 `task_update` 在 `refreshTasks()` 的响应**之后**到达，`upsertTask` 会正确地更新；如果在**之前**到达，随后 `refreshTasks` 的**整体覆盖**会把这条更新冲掉：

```js
// App.vue:283
tasks.value = Array.isArray(data) ? data : []   // ← 整体替换，非合并
```

这是个**从代码推导的竞态**（窗口极小，需实测确认概率），修法是让 `refreshTasks` 走 `upsertTask` 逐条合并而不是整体赋值。

### 4.3 登录 / 注册 / 登出

```js
// App.vue:161-166
function persistAuth(token, currentUsername) {
  authToken.value = token
  username.value = currentUsername
  localStorage.setItem(tokenKey, token)
  localStorage.setItem(usernameKey, currentUsername)
}
```

```js
// App.vue:380-395（登录）
async function handleLogin(payload) {
  authLoading.value = true
  try {
    const data = await login(payload)
    persistAuth(data.token, data.username)
    initTaskStream()                 // ★ 登录后立刻建 SSE
    setMessage(`登录成功，欢迎你 ${data.username}`, 'success')
    await refreshTasks(); await refreshAgents(); await refreshConversations()
  } catch (error) {
    setMessage(`登录失败：${error.message}`, 'error')
  } finally { authLoading.value = false }
}
```

登出则是一次"**集中清空**"：

```js
// App.vue:168-182
function clearAuth() {
  closeTaskStream()          // ① 关 SSE
  authToken.value = ''       // ② 清内存 token
  username.value = ''
  tasks.value = []           // ③ 清所有业务状态
  chatInput.value = ''
  searchId.value = ''
  searchResult.value = null
  agents.value = []
  selectedAgentId.value = ''
  conversations.value = []
  toolEvents.value = []
  localStorage.removeItem(tokenKey)      // ④ 清持久化
  localStorage.removeItem(usernameKey)
}
```

**这里有个容易被忽略的好设计**：`clearAuth()` 是**被 401 复用的**（见 §4.4），所以"登出"和"登录失效"走的是同一条清理路径——`closeTaskStream()` 一定先执行，**不会出现"已登出但 SSE 还挂着"**。

**但清空不彻底**：`clearAuth` 没有重置 `chatModalAgentId` / `chatModalInput`（[App.vue:35-36](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L35-L36)），也没有重置 `message`/`messageType`。若在独立对话弹窗打开时 token 失效，`clearAuth` 清掉 `agents` 后模板的 `v-if="chatModalAgentId && chatModalAgent"`（[App.vue:973](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L973)）因 `chatModalAgent` 变 null 而自动隐藏，所以视觉上不会残留——**属于"碰巧被兜住"，不是显式处理**。

### 4.4 ⚠️ 401 的处理覆盖度：**只有一处处理了**

这是本篇重点核查项。先看唯一处理了 401 的地方：

```js
// App.vue:278-293
async function refreshTasks() {
  if (!authToken.value) return
  try {
    const data = await getTasks(authToken.value)
    tasks.value = Array.isArray(data) ? data : []
    setMessage(`任务列表已刷新，共 ${tasks.value.length} 条记录`, 'success')
  } catch (error) {
    if (error?.status === 401) {        // ★★ 全站唯一的 401 分支
      clearAuth()
      setMessage('登录状态已失效，请重新登录', 'error')
    } else {
      setMessage(`任务列表拉取失败：${error.message}`, 'error')
    }
  }
}
```

`error.status` 之所以存在，是因为 `apiRequest` 把 HTTP 状态码挂到了 Error 上：

```js
// client.js:24-30
if (!response.ok) {
  const message = data?.error || data?.message || `HTTP ${response.status}`
```

## 5. SSE 消费链路

### 5.1 连接是怎么建立的：token 放在 **URL query**

```js

  return new EventSource(buildApiUrl(`/api/tasks/stream?token=${encodeURIComponent(token)}`))
```

为什么放 URL？后端注释给了原因：


这是**浏览器 `EventSource` 的固有限制**（原生 API 不支持自定义请求头），所以"token 进 URL"不是随手写的，而是**被 API 逼出来的妥协**。代价见 §12.1。

App 侧：


**两个事件的语义差异**：

| 事件 | 载荷 | 前端动作 | 存储位置 |
|---|---|---|---|
| `task_update` | 完整 `Task`（含 `id/status/result/error/agent_id`） | `upsertTask` **覆盖/插入** | `tasks`（全局共享） |
| `tool_call` | `ToolCallEvent`（`task_id/tool_name/status/arguments/result/error/timestamp`） | `push` **追加** | `toolEvents`（只增不减） |

### 5.3 `upsertTask` 的合并语义：**不是合并，是整体替换**

```js
// App.vue:184-191
function upsertTask(updatedTask) {
  const index = tasks.value.findIndex((task) => task.id === updatedTask.id)
  if (index >= 0) {
    tasks.value[index] = updatedTask     // ★ 整体替换，逐字段合并
    return
  }
  tasks.value.unshift(updatedTask)       // ★ 新任务插到最前
}
```

**语义澄清**：

1. **命中即整对象替换**（不是 `Object.assign(existing, updated)`）。所以**推送的载荷必须是"完整的 Task"**——只要后端某天改成"只推变化字段"（增量事件），前端就会把任务的其他字段抹成 `undefined`。当前之所以能工作，是因为后端推的就是完整 `model.Task`（`handler.go:400`）。**这是一条隐式契约**（代码事实）。
2. **未命中则 `unshift` 到数组头部**。所以 `tasks` 数组内是"新任务在前"，但**这不等于按时间倒序**：一条老任务被 SSE 更新为"未命中"时的插入位置只取决于"当前是否已在列表"。真正的排序由各视图的 `computed` 负责（见 §6.3）。
3. **是否依赖推送顺序**：**位置依赖推送顺序（新任务在头部），但展示顺序不依赖**——`activeAgentTasks` / `chatModalTasks` 会重新按 `created_at` 排序。**唯一依赖顺序的是"更新到达前 `refreshTasks` 的整体覆盖"竞态**（见 §4.2）。

### 5.4 断线重连：手写固定 5 秒，**关掉浏览器原生自动重连**

```js
// App.vue:268-275
taskEventSource.onerror = () => {
  closeTaskStream()                    // ★ 先关掉（这会阻止浏览器原生重连）
  setTimeout(() => {
    if (authToken.value) {
      initTaskStream()                 // ★ 5 秒后重建
    }
  }, 5000)
}
```

这里有个**很容易被忽略的取舍**：

- `EventSource` **默认自带自动重连**（且默认带 `retry:` 退避）；
- 一旦调用 `.close()`，浏览器就**不再自动重连**；
- 所以本实现是**"主动放弃原生重连、改用手写固定 5 秒重连"**。

**为什么可能是刻意**：因为 token 在 URL 里，如果服务端会话变化，浏览器原生重连会**沿用旧 URL（旧 token）**，而手写重建能**重新读取当前 `authToken.value`**（登录/换号后能带新 token）。

**但代价有两个（均为代码事实）**：

1. **固定 5 秒、无退避、无抖动**——断网时全体客户端每 5 秒同步重连一次（惊群）；
2. **重连不做数据补拉**——`onerror` 里**没有调用 `refreshTasks()`**。断连窗口内产生并推送完的 `task_update` **永久丢失**，客户端会一直停留在旧状态（比如永远显示"processing"），直到用户手动触发一次刷新（发消息 / 切 Agent 面板点运行）。**没有轮询兜底**。

| 时机 | 是否关闭 | 依据 |

**三条必须讲清的语义**：

1. **过滤键是 `agent_id`，不是 `conversation_id`**。对话里显示的"整段历史 = 这个 Agent 的全部任务"，**跨会话也一起显示**。
2. **排序键是 `created_at` 升序**（旧消息在上、新消息在下，符合聊天直觉）。用户气泡取 `task.payload`（[App.vue:801](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L801)），Agent 气泡取 `assistantStatusText(task)`（其定义在 [App.vue:219-232](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L219-L232)，模板使用在 [App.vue:815](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L815)）。
3. **"当前会话"是另一条独立的线**，只用于**发消息时携带 `session_id`**：

```js
// App.vue:108-116
const conversationByAgent = computed(() => {
  const map = {}
  for (const conv of conversations.value) {
    if (conv.agent_id && !map[conv.agent_id]) {   // ★ 取"第一个" = 最近更新的那个
      map[conv.agent_id] = conv.id
    }
  }
  return map
})
```

它为什么"取第一个"就能拿到最新会话？因为**后端按 `updated_at desc` 返回**：

```go
// internal/queue/manager.go:759-762
func (m *TaskManager) ListConversations(userID uint) []*model.Conversation {
    var convs []*model.Conversation
    m.db.Where("user_id = ?", userID).Order("updated_at desc").Find(&convs)  // ★ 最新在前
    return convs
}
```

**这是一条隐式契约**：前端**假定** `GET /api/conversations` 第一条就是最新会话。后端排序一改，"当前会话"就会静默漂移。**（代码事实 + 跨层耦合）**

> ⚠️ **由此产生的最直观缺陷**：点"新对话"（[newConversation](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L346-L360)）确实新建了会话、也确实切换了 `session_id`，但**右侧对话区不会清空**——因为它按 `agent_id` 过滤，新会话的任务还没产生，旧会话的任务仍然全在屏幕上。用户会感觉"新对话没生效"。**（代码事实）**

关键点是 **`stroke: currentColor`**——图标颜色跟随文字色，因此**主题色/状态色的变化会自动传导到图标**，不需要为每个图标写颜色。示例（导航图标，[App.vue:638-663](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L638-L663)）：

## 12. 已知缺陷与未验证项

> 标注规则：**【代码事实】**= 读代码即可确认；**【代码推导】**= 由代码结构推出的后果，未运行验证；**【需实测】**= 必须跑起来才能确认。

### 12.1 🔴 高：token 通过 URL query 传输，且会被重复泄露

```js
// client.js:104-106
return new EventSource(buildApiUrl(`/api/tasks/stream?token=${encodeURIComponent(token)}`))
```

**【代码事实】** token 出现在 SSE 请求的 URL 里，会进入：

1. **浏览器历史/地址栏**（虽然是 EventSource 内部请求，不写地址栏，但会进浏览器网络日志）；
2. **Nginx / 反向代理的 access log**（`nginx.conf:46-60` 的 `location /api/tasks/stream` 会记录 `$request`，含 query）；
3. **任何中间网关、APM**；
4. 若页面内有指向本域的链接，历史 Referer 也可能带上。

**这是 `EventSource` 不支持自定义 Header 导致的**（后端注释已说明，`handler.go:358-360`）。修法方向（未实施）：改用 `fetch` + `ReadableStream` 手写 SSE（可带 `Authorization` 头），或引入 `@microsoft/fetch-event-source` 之类的库；退一步至少要**把 token 换成短时效的一次性 stream ticket**。

### 12.2 🔴 高：401 处理只落实在 `refreshTasks` 一处（覆盖率 ~1/13）

见 §4.4。**【代码事实】** 结论：**token 过期后应用不会自动登出**，13 处调用点里只有 1 处（`refreshTasks`）会 `clearAuth()`；用户会看到一个"看似已登录、但什么都点不动、每次都报错"的界面。这是**横切关注点被散落实现**的典型后果。修法：在 `apiRequest` 里集中拦截 401。

### 12.3 🟠 中：SSE 断线后无数据补拉，事件永久丢失

```js
// App.vue:268-275
taskEventSource.onerror = () => {
  closeTaskStream()
  setTimeout(() => { if (authToken.value) initTaskStream() }, 5000)   // ← 只重连，不补数据
}
```

**【代码事实】** 重连逻辑里**没有 `refreshTasks()`**。断连窗口内已推送完的 `task_update` 无从恢复（**没有轮询兜底**），界面会永久停在旧状态。修法：`onerror` 重连成功后立即 `refreshTasks()` 做一次全量对齐（这正是 REST+SSE 混合模式该有的"重连即 resync"）。

### 12.4 🟠 中：重连固定 5 秒、无退避、无抖动

`setTimeout(..., 5000)`（[App.vue:270-274](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L270-L274)）。**【代码事实】** 服务端故障时全体客户端每 5 秒同步重连（惊群）；且**主动 `close()` 放弃了 `EventSource` 原生的自动重连能力**（原生重连本身带退避）。修法：指数退避 + 抖动，或直接改用原生重连（代价是要接受旧 token）。

### 12.5 🟠 中：`upsertTask` 是整对象替换，不是字段合并

```js
// App.vue:186-188
if (index >= 0) { tasks.value[index] = updatedTask; return }   // 覆盖，非 merge
```

**【代码事实】** 要求"推送载荷必须是完整 Task"。一旦后端改推增量事件（只带变化字段），前端会把其他字段抹成 `undefined`。**这是一条隐式契约，且没有任何校验**。

### 12.6 🟠 中：token 无效时 SSE 会**无限重连**

`initTaskStream` 只判断 `authToken.value` 是否为**非空字符串**（[App.vue:240](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L240)），不判断有效性。**【代码推导】** 若 localStorage 里是一个已失效的 token：`onerror` 触发 → 5 秒后 `initTaskStream` → 后端再次 401 → 循环，**每 5 秒一次、永不停止**，且**不会触发登出**（因为 `refreshTasks` 可能根本没被调用）。这是一条"静默的资源浪费 + 用户困惑"路径，**需实测确认**。

### 12.7 🟠 中：对话按 `agent_id` 过滤，而非 `conversation_id`；"新对话"不清屏

见 §6.3。**【代码事实】** `activeAgentTasks` / `chatModalTasks` 都只按 `agent_id` 过滤（[App.vue:118-122,139-143](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L118-L143)）。后果：

- 点"新对话"后，右侧对话区**不会清空**，"新会话"只影响 `session_id`；
- **同一 Agent 的所有会话历史混在一起显示**，用户无法区分"这条属于哪次会话"。

修法：过滤键改为 `(agent_id, session_id)` 组合，或后端在 Task 上返回 `conversation_id` 供前端过滤。

### 12.8 🟠 中：`conversationByAgent` 依赖后端排序，属跨层隐式契约

```js
// App.vue:111-113
if (conv.agent_id && !map[conv.agent_id]) { map[conv.agent_id] = conv.id }  // 取第一条
```

**【代码事实】** 之所以"取第一条"就等于"取最新会话"，是因为后端 `Order("updated_at desc")`（`manager.go:761`）。**前端没有排序、没有按时间比较**。后端排序一改（例如改成 `created_at`），"当前会话"会静默变成"最早创建的会话"，用户历史会串。**需实测**：会话列表顺序 → 发消息落到哪个 session。

## 14. 一页速记（面试/复盘用）

- **一句话定位**：X3 是一个 **只依赖 Vue3、零路由零 store 零组件库** 的独立 SPA，用 `App.vue` 一个 `ref` 管五视图、一个 `tasks` 数组管全局任务真相、一条 `EventSource` 管实时更新。
- **五个最容易被追问的设计点**：
  1. **为什么没有路由/状态库？** —— 五视图切换只需一个 `activeView` 字符串（[App.vue:47](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L47)），状态靠"父持有 + props/emit"传递（[App.vue:874-879](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L874-L879)）。收益是零依赖零冲突，代价是**横切逻辑必须手写**——401 拦截和 SSE 重连都因此漏了边界。
  2. **SSE 的 token 为什么在 URL 里？** —— `EventSource` 不支持自定义 Header（后端注释 [handler.go:358-360](file:///d:/Program%20Files/GoTaskAI/internal/api/handler.go#L358-L360)），只能 `?token=`。**这是被浏览器 API 逼出来的妥协，但会把 token 送进代理日志**。
  3. **对话消息怎么按 Agent/会话切分？** —— `activeAgentTasks = tasks.filter(agent_id == 选中).sort(created_at asc)`（[App.vue:118-122](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L118-L122)）。**只按 agent_id，不按 conversation_id** → "新对话"不会清屏，同一 Agent 的所有会话历史混在一起。
  4. **SSE 到达后怎么更新状态？** —— `upsertTask`（[App.vue:184-191](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L184-L191)）：**命中即整对象替换、未命中 unshift**。所以要求推送载荷是**完整 Task**（当前后端确实推完整对象，`handler.go:400`），这是一条隐式契约。
  5. **自动滚动为什么要三处补偿？** —— `watch` 只盯着 `activeAgentTasks.length`，而"pending→completed"是**替换同一元素、长度不变**，watcher 抓不到，所以 SSE 回调里必须再补一次 `scrollChatToBottom()`（[App.vue:248-250](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L248-L250)）。
- **五个必须说清的事实修正（缺陷）**：
  1. **401 只在 `refreshTasks` 一处处理**（[App.vue:286-288](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L286-L288)）——13 处调用点里 1 处落实，**token 过期不会自动登出**。
  2. **token 走 URL**（`client.js:104-106`），会进 Nginx/网关日志；**且重连固定 5 秒无退避**，无效 token 会**无限重连**（[App.vue:268-275](file:///d:/Program%20Files/GoTaskAI/web/src/App.vue#L268-L275)）。
  3. **SSE 断线不补拉** —— `onerror` 只重连、不 `refreshTasks`，**没有轮询兜底**，断线期间完成的推送永久丢失。
  4. **三个组件 + 三个 API 函数是死代码**：`TaskSubmit.vue` / `TaskList.vue` / `PlaceholderPanel.vue` 从未被 import；`submitTask` / `batchSubmitTasks` / `deleteSession` 从未被调用。
  5. **`web/dist/` 已提交进仓库，且 Go 服务托管的不是它** —— `r.StaticFile("/")` 指向旧的 `public/index.html`（[main.go:120](file:///d:/Program%20Files/GoTaskAI/cmd/api/main.go#L120)），新前端要靠 Vite dev / Nginx 单独提供。
- **三条可量化的证据**：
  - §13.3：Network 里那条 `eventsource` 请求的 URL **明文带 token**，且 Messages 面板能看到 `event: task_update` / `event: tool_call` → 证明 SSE 契约与 §12.1 风险；
  - §13.4：把 localStorage token 改坏后，**不刷新页面**只会不断报错、不会登出；**刷新页面**才会登出 → 证明 401 覆盖度只有 1 处；
  - §13.5：`git ls-files web/dist` 有输出 且 `http://localhost:8080/` 打开的是旧页面 → 证明"构建产物已提交 + 与新前端未接线"。
